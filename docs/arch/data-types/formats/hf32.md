## Purpose and scope

`HF32` is an assigned PTO floating format stored in a thirty-two-bit carrier, and this unit is the exact owner of its layout, encoding validity, finite decomposition, classification, canonical NaN, and signed zero encodings.

Its eleven-bit fraction is one bit wider than the `TF32` fraction, so the two truncated carriers are distinct formats even though both occupy thirty-two bits.

<!-- PTO-READER-BLOCK: arch-format-hf32-concepts role=concepts-state -->
## Carrier and fields

Design point: the rounding boundary from `FP32` to `HF32` is not part of this unit, so which discarded `FP32` fraction bits are acceptable is decided by the consumer that performs the conversion.

The descriptor uses a `32`-bit carrier, a `32`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `31`, `8` exponent bit(s) in `30:23`, `11` fraction bit(s) in `22:12`, exponent bias `127`, and `12` required low zero bits.

Design point: the required zero bits are exactly the low bits that a wider carrier must discard, so a carrier produced by narrowing the wider format always passes the encoding check, and a carrier with any of those bits set could not have come from that narrowing.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-hf32-rules role=rules-interactions -->
## Decomposition and classification

Design point: because the eleven fraction bits sit at `22:12`, every bit the consumer discards when narrowing from `FP32` is one of the `12` low bits that this format requires to be zero.

`HF32EncodingValid` reports whether those `12` required low bits are all zero, and the descriptor sets `required_high_zero_bits` to `0`.

`HF32FiniteDecomposition` first rejects any carrier whose `12` low bits are not zero, then returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

Design point: truncating the fraction changes how finely a value can be represented without changing the exponent encoding, so a truncated carrier keeps the `FP32` range and loses precision uniformly across it.

<!-- PTO-READER-BLOCK: arch-format-hf32-boundaries role=boundaries -->
## Boundaries and exact encodings

`ClassifyHF32` assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes, and `HF32CanonicalNaN` returns `0x7fc00000`.

An exponent field of zero with a nonzero fraction selects the subnormal form, and an all-one exponent is never finite: a zero fraction gives infinity and a nonzero fraction gives a NaN class.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

For example, `0x00001000` is the smallest positive subnormal and decomposes to a positive significand of `1` with exponent `-137`, while `0x7f800000` is positive infinity and reports no finite decomposition.

Design point: requiring `12` low zero bits makes every valid finite `HF32` carrier denote the same value as the `FP32` carrier with the same bits, because the eleven `HF32` fraction bits at `22:12` are the top eleven `FP32` fraction bits; without that rule the same thirty-two-bit pattern could denote an `FP32` value and an `HF32` value with different magnitudes.
