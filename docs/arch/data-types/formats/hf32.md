## Purpose and scope

HF32 is an assigned PTO numeric format. This page helps a reader connect its carrier layout, finite-value decomposition, and value classification; the exact contract remains in `HF32NumericFormatDescriptor`, `HF32FiniteDecomposition`, and `ClassifyHF32` in the ASL owner.

<!-- PTO-READER-BLOCK: arch-format-hf32-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `32`-bit carrier, a `32`-bit logical lane, and `1` lane(s) per carrier. The lane has one sign bit at position `31`, `8` exponent bit(s), `11` fraction bit(s), and exponent bias `127`.

Bits `11:0` must be zero. The eleven stored fraction bits occupy `22:12`, so nonzero low bits make the carrier invalid before finite decomposition.

<!-- PTO-READER-BLOCK: arch-format-hf32-rules role=rules-interactions -->
## Decomposition and classification

`HF32FiniteDecomposition` reports whether a finite decomposition is available and, when available, returns the sign, an integer significand, and a binary exponent. `ClassifyHF32` separately assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes supported by this format.

It has signed zero, subnormals, infinities, quiet NaNs, and signaling NaNs among valid carriers. An all-one exponent is not a finite decomposition.

<!-- PTO-READER-BLOCK: arch-format-hf32-boundaries role=boundaries -->
## Boundaries and exact encodings

`0x00000000` and `0x80000000` are positive and negative zero; `0x7fc00000` is the canonical quiet NaN.

The finite-decomposition function reports availability with its returned tuple; value classification is a separate function result.

This example illustrates how to read the functions; it does not add an encoding rule.
