## Purpose and scope

`BF16` is an assigned PTO floating format stored in a sixteen-bit carrier, and this unit is the exact owner of its layout, finite decomposition, value classification, canonical NaN, and signed zero encodings.

It keeps the `FP32` exponent width and shortens the fraction to seven bits, so its range matches `FP32` while its precision is lower.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-bf16-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `16`-bit carrier, a `16`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `15`, `8` exponent bit(s) in `14:7`, `7` fraction bit(s) in `6:0`, and exponent bias `127`.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0`, so every sixteen-bit lane is a defined encoding.

<!-- PTO-READER-BLOCK: arch-format-bf16-rules role=rules-interactions -->
## Decomposition and classification

`BF16FiniteDecomposition` returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

`ClassifyBF16` assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes, so the format supports infinities, quiet NaNs, and signaling NaNs as well as finite values.

An exponent field of zero with a nonzero fraction selects the subnormal form, and an all-one exponent is never finite: a zero fraction gives infinity and a nonzero fraction gives a NaN class.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-bf16-boundaries role=boundaries -->
## Boundaries and exact encodings

The all-ones exponent clause returns an unavailable decomposition without a separate infinity or NaN branch, so the decomposition reports the format's restriction while `ClassifyBF16` reports the value class.

Design point: the decomposition returns an integer significand and exponent rather than a host floating-point value, so a consumer that needs an exact result multiplies by a power of two instead of relying on host rounding.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0x0001` is the smallest positive subnormal and denotes `1 * 2^-133`; `0x0080` is the first positive normal and denotes `0x0080 * 2^-133`, which is `1 * 2^-126`.

`0x7f7f` is the largest finite value and decomposes to significand `0x00ff` with exponent `120`, which is `1.9921875 * 2^127`.

pure func ClassifyBF16(value: bits(16)) => NumericValueClass
begin

    let fraction = value[6:0];
