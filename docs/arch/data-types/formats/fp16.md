## Purpose and scope

`FP16` is an assigned PTO floating format stored in a sixteen-bit carrier, and this unit is the exact owner of its layout, finite decomposition, value classification, canonical NaN, and signed zero encodings.

It spends five exponent bits and ten fraction bits, so it trades exponent range for a finer value grid than `BF16`.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-fp16-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `16`-bit carrier, a `16`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `15`, `5` exponent bit(s) in `14:10`, `10` fraction bit(s) in `9:0`, and exponent bias `15`.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0`, so every sixteen-bit lane is a defined encoding.

<!-- PTO-READER-BLOCK: arch-format-fp16-rules role=rules-interactions -->
## Decomposition and classification

`FP16FiniteDecomposition` returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

`ClassifyFP16` assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes, so the format supports infinities, quiet NaNs, and signaling NaNs as well as finite values.

An exponent field of zero with a nonzero fraction selects the subnormal form, and an all-one exponent is never finite: a zero fraction gives infinity and a nonzero fraction gives a NaN class.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-fp16-boundaries role=boundaries -->
## Boundaries and exact encodings

The all-ones exponent clause returns an unavailable decomposition without a separate infinity or NaN branch, so the decomposition reports the format's restriction while `ClassifyFP16` reports the value class.

Design point: five exponent bits give a normal range of `2^-14` up to just under `2^16`, so a value that fits `FP32` precision can still overflow `FP16` and must be handled by the consumer.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0x0001` is the smallest positive subnormal and denotes `1 * 2^-24`; `0x0400` is the first positive normal and denotes `0x0400 * 2^-24`, which is `1 * 2^-14`.

`0x7bff` is the largest finite value and decomposes to significand `0x07ff` with exponent `5`, which is `1.9990234375 * 2^15`.

pure func ClassifyFP16(value: bits(16)) => NumericValueClass
begin
    let exponent = value[14:10];
    let fraction = value[9:0];
    if exponent == Ones{5} then
        if fraction == Zeros{10} then
            if value[15] == '1' then return NumericValue_NegativeInfinity;

        exponent == Zeros{5} && fraction != Zeros{10});
