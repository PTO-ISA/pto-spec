## Purpose and scope

E2M3 is an assigned PTO numeric format. This page helps a reader connect its carrier layout, finite-value decomposition, and value classification; the exact contract remains in `E2M3NumericFormatDescriptor`, `E2M3FiniteDecomposition`, and `ClassifyE2M3` in the ASL owner.

<!-- PTO-READER-BLOCK: arch-format-e2m3-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `8`-bit carrier, a `6`-bit logical lane, and `1` lane(s) per carrier. The lane has one sign bit at position `5`, `2` exponent bit(s), `3` fraction bit(s), and exponent bias `1`.

Bits `7:6` of the eight-bit carrier must be zero; the six-bit value occupies bits `5:0`.

<!-- PTO-READER-BLOCK: arch-format-e2m3-rules role=rules-interactions -->
## Decomposition and classification

`E2M3FiniteDecomposition` reports whether a finite decomposition is available and, when available, returns the sign, an integer significand, and a binary exponent. `ClassifyE2M3` separately assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes supported by this format.

It has signed zero and subnormals, but no infinity or NaN class. A carrier with either constrained high bit set is rejected by the encoding-validity and finite-decomposition functions.

<!-- PTO-READER-BLOCK: arch-format-e2m3-boundaries role=boundaries -->
## Boundaries and exact encodings

Encodings `0x00` and `0x20` are positive and negative zero.

The finite-decomposition function reports availability with its returned tuple; value classification is a separate function result.

This example illustrates how to read the functions; it does not add an encoding rule.

For example, `0x01` decomposes to positive significand `1` with exponent `-3`; `0x40` is not a valid E2M3 encoding because bit `6` is set.
