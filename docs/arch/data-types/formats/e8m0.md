## Purpose and scope

`E8M0` is an assigned PTO scale format stored entirely in an eight-bit carrier, and this unit owns its descriptor, finite decomposition, classification, canonical NaN, and the scale-block element count.

The format encodes powers of two only: each eight-bit lane denotes one power of two, and the unit also reports the hardware scale-block element count.

<!-- PTO-READER-BLOCK: arch-format-e8m0-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `8`-bit carrier, a `8`-bit logical lane, and `1` lane per carrier.

The lane has no sign bit and no fraction bit: all `8` bits in `7:0` form the exponent field, exponent bias `127`, and the descriptor reports `NumericFormatKind_E8M0` rather than a fixed binary kind.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0` and the format applies no separate encoding-validity check, so every eight-bit lane is a defined encoding.

## Decomposition and classification

`E8M0FiniteDecomposition` returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`; the significand is always `1` and the exponent is the raw code minus `127`.

`ClassifyE8M0` assigns a non-all-ones code to the positive normal class and the all-ones code to quiet NaN; the format has no zero, no signed zero, no subnormal, no infinity, and no signaling NaN.

The all-ones code `0xff` makes the decomposition unavailable and classification returns the quiet NaN class, and every other code is an available finite power of two.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-e8m0-boundaries role=boundaries -->
## Boundaries and exact encodings

Design point: because the significand is fixed at `1`, the code space maps one-to-one onto whole-number exponents, so a consumer converts a scale code by arithmetic on the exponent rather than on a fraction.

`0x00` is the smallest code and denotes exponent `-127`; `0xfe` is the largest finite code and denotes exponent `127`.

Design point: the format declares no zero encoding at all, so zero is not a value of this type; converting a zero source to `E8M0` publishes `0xff` with an invalid-operation status instead of a zero code.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.
