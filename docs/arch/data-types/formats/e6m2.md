## Purpose and scope

`E6M2` is an assigned PTO scale format stored in an eight-bit carrier, and this unit owns its descriptor, finite decomposition, exact finite value, classification, and canonical NaN.

It is the standalone description of the same decoder that the `PTO-CUBE-HIF4-SCALE-001` contract reuses for the `E6M2` field of a HiF4 scale word.

<!-- PTO-READER-BLOCK: arch-format-e6m2-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `8`-bit carrier, a `8`-bit logical lane, and `1` lane per carrier.

The lane has no sign bit: `6` exponent bit(s) in `7:2`, `2` fraction bit(s) in `1:0`, exponent bias `48`, and a hidden leading one in the finite significand.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0` and the format applies no separate encoding-validity check, so every eight-bit code is a defined encoding.

<!-- PTO-READER-BLOCK: arch-format-e6m2-rules role=rules-interactions -->
## Decomposition and classification

`E6M2FiniteDecomposition` returns an available decomposition for every code except `0xff`, with sign false, integer significand `4` plus the fraction, and binary exponent equal to the exponent field minus `48` minus `2`.

`E6M2FiniteValue` returns `(4 + fraction) / 4 * FP19PowerOfTwo(exponent - 48)`, and `ClassifyE6M2` returns quiet NaN for `0xff` and the positive normal class for every other code.

Codes `0x00` through `0xfe` are finite positive normal values, and `0xff` is the quiet-NaN code with no finite decomposition; the format has no zero, signed zero, subnormal, infinity, or signaling NaN.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-e6m2-boundaries role=boundaries -->
## Boundaries and exact encodings

Design point: the all-ones code is excluded before finite-value evaluation, so `E6M2FiniteValue` asserts on `0xff` and a consumer must classify the code first instead of calling the decoder on every code in the space.

`0x00` is the smallest finite code and denotes `2^-48`; `0xfe` is the largest finite code and denotes `1.5 * 2^15`.

Design point: the format declares no zero encoding at all, so zero is not a value of this type; converting a zero source to `E6M2` publishes the `0x00` carrier, which denotes `2^-48`.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0xff` is both the sole quiet-NaN code and the canonical NaN returned by `E6M2CanonicalNaN`, and `E6M2FiniteValue` asserts that its argument is not `0xff`.

Because the hidden leading one is part of every code, the base scale is never zero, so a scale word always has a defined finite base unless its `E6M2` field is `0xff`.
