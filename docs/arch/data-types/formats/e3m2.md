## Purpose and scope

`E3M2` is an assigned PTO numeric format whose value occupies a six-bit lane inside an eight-bit carrier, and this unit owns its descriptor, encoding validity, finite decomposition, value classification, and signed zero encodings.

Three exponent bits and two fraction bits give a wider range than `E2M3` at the cost of one fraction bit.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-e3m2-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `8`-bit carrier, a `6`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `5`, `3` exponent bit(s) in `4:2`, `2` fraction bit(s) in `1:0`, and exponent bias `3`; bits `7:6` of the carrier are constrained to zero.

The descriptor sets `required_high_zero_bits` to `2`, so only the low six bits of the carrier belong to the value.

<!-- PTO-READER-BLOCK: arch-format-e3m2-rules role=rules-interactions -->
## Decomposition and classification

`E3M2EncodingValid` reports whether carrier bits `7:6` are both zero, and `E3M2FiniteDecomposition` rejects a carrier whose constrained bits are not zero before returning availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

`ClassifyE3M2` assigns the raw lane to zero, subnormal, or normal classes; the format has no infinity and no NaN encoding, so every six-bit lane denotes a finite value.

An exponent field of zero with a nonzero fraction selects the subnormal form, and every nonzero lane is classified as a signed finite value.

<!-- PTO-READER-BLOCK: arch-format-e3m2-boundaries role=boundaries -->
## Boundaries and exact encodings

Design point: constraining the two high carrier bits means an eight-bit storage byte can only carry one `E3M2` value, so the unused bits stay zero instead of being reinterpreted as a wider exponent.

`0x01` is the smallest positive subnormal and denotes `1 * 2^-4`; `0x08` is the second positive normal and denotes `4 * 2^-4`, which is `1 * 2^-1`.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0x1f` is the largest finite value and decomposes to significand `7` with exponent `2`, which is `1.75 * 2^4`.

`0x00` and `0x20` are the positive and negative zero encodings, and `0x40` is not a valid `E3M2` encoding because bit `6` is set.
