## Purpose and scope

`FP32` is an assigned PTO floating format stored in a thirty-two-bit carrier, and this unit is the exact owner of its layout, finite decomposition, value classification, canonical NaN, and signed zero encodings.

Its eight exponent bits and twenty-three fraction bits make it the widest binary format that fits in a thirty-two-bit carrier.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-fp32-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `32`-bit carrier, a `32`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `31`, `8` exponent bit(s) in `30:23`, `23` fraction bit(s) in `22:0`, and exponent bias `127`.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0`, so every thirty-two-bit lane is a defined encoding.

<!-- PTO-READER-BLOCK: arch-format-fp32-rules role=rules-interactions -->
## Decomposition and classification

`FP32FiniteDecomposition` returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

`ClassifyFP32` assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes, so the format supports infinities, quiet NaNs, and signaling NaNs as well as finite values.

An exponent field of zero with a nonzero fraction selects the subnormal form, and an all-one exponent is never finite: a zero fraction gives infinity and a nonzero fraction gives a NaN class.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-fp32-boundaries role=boundaries -->
## Boundaries and exact encodings

The all-ones exponent clause returns an unavailable decomposition without a separate infinity or NaN branch, so the decomposition reports the format's restriction while `ClassifyFP32` reports the value class.

Design point: requiring no zero bits keeps every thirty-two-bit pattern a defined value, so this unit never rejects a carrier and needs no encoding-validity function.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0x00000001` is the smallest positive subnormal and denotes `1 * 2^-149`; `0x00800000` is the first positive normal and denotes `0x00800000 * 2^-149`, which is `1 * 2^-126`.

`0x7f7fffff` is the largest finite value and decomposes to significand `0x00ffffff` with exponent `104`, which is `1.9999998807907104 * 2^127`.

    => (boolean, boolean, Word, integer {-1074..1023})
begin

    let fraction = value[22:0];

pure func ClassifyFP32(value: bits(32)) => NumericValueClass
begin
    let exponent = value[30:23];
    let fraction = value[22:0];
    if exponent == Ones{8} then
        if fraction == Zeros{23} then
            if value[31] == '1' then return NumericValue_NegativeInfinity;
            else return NumericValue_PositiveInfinity;
            end;
        elsif fraction[22] == '1' then return NumericValue_QuietNaN;
        else return NumericValue_SignalingNaN;
        end;
    end;
    return NumericValueClassFromFiniteSign(value[31],
        exponent == Zeros{8} && fraction == Zeros{23},
        exponent == Zeros{8} && fraction != Zeros{23});
end;
