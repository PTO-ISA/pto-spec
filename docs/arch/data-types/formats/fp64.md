## Purpose and scope

`FP64` is an assigned PTO floating format whose lane fills a whole `Word`, and this unit is the exact owner of its layout, finite decomposition, value classification, canonical NaN, and signed zero encodings.

Its eleven exponent bits and fifty-two fraction bits make it the widest format in this data-type family.

Design point: the record keeps the carrier width and the logical lane width separate, so a packed type reports two lanes in one carrier while a single-lane type reports only its own lane width in its carrier.

<!-- PTO-READER-BLOCK: arch-format-fp64-concepts role=concepts-state -->
## Carrier and fields

The descriptor uses a `64`-bit carrier, a `64`-bit logical lane, and `1` lane per carrier.

The lane has one sign bit at position `63`, `11` exponent bit(s) in `62:52`, `52` fraction bit(s) in `51:0`, and exponent bias `1023`.

The descriptor sets `required_low_zero_bits` and `required_high_zero_bits` to `0`, so every sixty-four-bit lane is a defined encoding.

<!-- PTO-READER-BLOCK: arch-format-fp64-rules role=rules-interactions -->
## Decomposition and classification

`FP64FiniteDecomposition` returns availability, the sign, an integer significand, and a binary exponent such that the exact value is `(-1)^sign * UInt(significand) * 2^exponent`.

`ClassifyFP64` assigns the raw lane to zero, subnormal, normal, infinity, or NaN classes, so the format supports infinities, quiet NaNs, and signaling NaNs as well as finite values.

An exponent field of zero with a nonzero fraction selects the subnormal form, and an all-one exponent is never finite: a zero fraction gives infinity and a nonzero fraction gives a NaN class.

Design point: writing `FALSE` for availability instead of an arbitrary significand keeps a consumer from reading the placeholder fields of a non-finite carrier as a number, so the availability flag must be consulted first.

<!-- PTO-READER-BLOCK: arch-format-fp64-boundaries role=boundaries -->
## Boundaries and exact encodings

The all-ones exponent clause returns an unavailable decomposition without a separate infinity or NaN branch, so the decomposition reports the format's restriction while `ClassifyFP64` reports the value class.

Design point: the returned exponent is an integer whose declared range reaches `-1074`, so the subnormal form of the smallest carrier is expressible without host arithmetic.

Design point: `0x00` and the negative encoding are separate encodings of the same magnitude, so a consumer that preserves the sign bit can still tell which one produced a result even when both compare equal to zero.

Read this page in the order of the functions: take the field positions from the descriptor, call the classification function when the value class matters, and call the decomposition function when the exact significand and exponent are needed.

## Non-normative reading example

This example illustrates the current ASL owner and does not replace the normative operation.

`0x1` is the smallest positive subnormal and denotes `1 * 2^-1074`; `0x0010000000000000` is the first positive normal and denotes `0x0010000000000000 * 2^-1074`, which is `1 * 2^-1022`.

`0x7fefffffffffffff` is the largest finite value and decomposes to significand `0x001fffffffffffff` with exponent `971`.

pure func ClassifyFP64(value: Word) => NumericValueClass
begin
    let exponent = value[62:52];
    let fraction = value[51:0];
    if exponent == Ones{11} then
        if fraction == Zeros{52} then
