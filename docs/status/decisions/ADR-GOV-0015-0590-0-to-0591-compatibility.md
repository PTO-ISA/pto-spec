# ADR-GOV-0015: PTO ISA 0.59.0.0 to 0.59.1 compatibility and release identity

## Context

The immutable prior publication is `v0.59.0.0` at
`b0165320a4b575b18d2f4d93faf40178f661ab49`. Issue #434 defines the release
scope. The owner inventory includes the accepted changes since that tag, along
with the source-symbol changes from #431. The normative details remain in the
linked ASL and NDF owners.

## Decision

Use architecture `0.59.1`, first publication `0.59.1.0`, and encoding ABI
`pto-isa-0.59.1-mode-function-v1`. Use the same encoding projection for
development and the release candidate. It binds 473 unqualified Scalar forms,
705 scoped Scalar forms, 105 command forms, and the current Tile selectors,
register locations and reserved encodings. The manifest selects all accepted
NDF clauses and binds the release-boundary ADR, whose inventory identifies
changed owners relative to the tagged baseline.

The main architectural changes include scoped Scalar GM, strided atomic TSTORE,
indexed TLSU bounds, Shared CUBE layout movement, predicate composition,
SUBVIEW recovery, the single-leader runtime ABI, and HSCB messaging and launch
geometry. The release boundary preserves the defaults and open questions in
those owners.

## Compatibility and consequence

The release is breaking for identity-bearing artifacts. Consumers must build
and link against the new exact ABI and digest. The 473 unqualified Scalar and
105 command forms retain their form IDs, opcode masks and matches, widths and
field layouts. The B.DATR and BSTART.TMOV constraint updates enter the new
identity under their owning ASL applicability rules. Scoped forms add
encodings to that inventory and enter the release digest.
Downstream ASL callers of renamed helpers need source migration. The existing
HSCB launch entry retains its signature and four-word payload and exposes
logical geometry `1/0` while the dispatch is outstanding.

Reusing the previous identity would obscure the scoped binary inventory and
architectural state changes. Counting the scoped forms only in development
would leave a published digest unable to identify an accepted encoding class.

## Verification obligations

Use the exact merged main commit and the pinned NDF and ASLRef inputs. Require
protected PR checks, release-readiness gates, the complete AVS matrix, and
artifact certification before publication. Separately validate downstream
compiler, runtime, ASL-MODEL and site integration in their owning workflows.

## Bilingual decision detail / 双语决策详述

### Why this decision / 为什么做出此决策

**English.** The post-release changes add scoped encodings and observable
architectural behavior. A distinct identity lets consumers select the complete
encoding inventory and validate compatibility against the previous publication.

**中文。** 上次发布之后增加了带 scope 的编码和架构可观察行为。独立发布身份使
下游能选择完整编码清单，并对照上一个发布版本验证兼容性。

### Detailed decision / 详细决策

**English.** Bind architecture `0.59.1`, publication `0.59.1.0` and the new
encoding ABI to the complete changed-owner inventory relative to `v0.59.0.0`.
Use the same form projection to compute the development and release digest.

**中文。** 架构号 `0.59.1`、发布号 `0.59.1.0` 和新的编码 ABI 对应相对
`v0.59.0.0` 的完整规范源差异清单。开发与发布指纹使用同一表单投影。

### What changed / 改动内容

#### English

- Add the 705 scoped Scalar forms to the release fingerprint.
- Carry the accepted memory, Tile and HSCB changes and the ASL helper rename
  into the new identity.
- Keep the release verification bound to one merged commit and its pins.

#### 中文

- 将 705 个带 scope 的 Scalar 表单纳入发布指纹。
- 在新身份下纳入已接受的内存、Tile、HSCB 变更和 ASL helper 重命名。
- 发布验证绑定到一个已合入提交及其依赖版本。

### Scope and boundaries / 范围与边界

**English.** ASL and NDF retain ownership of semantics and constraints.
Downstream toolchains and site publication have independent validation.

**中文。** ASL 与 NDF 继续负责语义和约束。下游工具链和站点发布各自独立验证。
