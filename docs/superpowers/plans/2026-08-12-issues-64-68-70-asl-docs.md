# Issues 64, 68, and 70 ASL and Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close GitHub issues #64, #68, and #70 in the normative ASL and documentation without producing or validating a release.

**Architecture:** Add two encoded-field layers that remain distinct from effective tile types: `DTYPE_NONE` is a five-bit sentinel resolved before tile allocation, while `B.FPATR` latches a typed `PostProcessConfig` used only by the 12 accepted CUBE operations. Preserve the existing one-level bundle model, preflight every derived type/operand/output before effects, and keep unresolved numeric arithmetic behind named profile hooks.

**Tech Stack:** ASL1 pinned by `.aslref-version`, JSON catalogs and requirements, Markdown instruction reference, repository Python/shell generators and checks.

## Global Constraints

- Do not run `make release-validate`, generate release-candidate evidence, publish a release, or edit candidate-result fields.
- Preserve all pre-existing dirty-worktree changes and do not revert, overwrite, or reformat unrelated edits.
- Keep `DTYPE_NONE` as encoded value 31; it MUST NOT become a `TileDataType` and MUST NOT acquire width, arithmetic, or U8/U32 default semantics.
- Effective DataType precedence is concrete `B.DATR`, then concrete BSTART DataType, then a TMOV Local/Shared source descriptor; unresolved required types fault with `Fault_TileLegality` before allocation, consumption, or payload effects.
- `B.FPATR` mask is `0x00007fff`, match is `0x00002023`, and canonical None is `0x00002023`.
- Exactly one `B.FPATR` is required for each of the 12 accepted CUBE operations; duplicate or inapplicable presence is a bundle-control fault, while invalid modes and operand schemas are tile-legality faults.
- Preserve direct explicit D and explicit C semantics, the one-level architecture, and existing profile boundaries for FP19 arithmetic and target numeric behavior.
- Issue #70 is a documentation consistency requirement: TMATMUL must use `LB0=M`, `LB1=N`, and `LB2=K`; no ASL symbol change is required because ASL stores positional dimension slots.
