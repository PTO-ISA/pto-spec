## 用途与范围

`E6M2` 是已分配的 PTO 缩放格式，存储在 `8` 位载体中；本单元拥有它的描述符、有限值分解、精确有限值、分类和规范 NaN。

它是对同一个解码器的独立描述，`PTO-CUBE-HIF4-SCALE-001` 契约会复用该解码器处理 HiF4 缩放字中的 `E6M2` 字段。

<!-- PTO-READER-BLOCK: arch-format-e6m2-concepts role=concepts-state -->
## 载体与字段

描述符使用 `8` 位载体、`8` 位逻辑 lane，并且每个载体包含 `1` 个 lane。

lane 没有符号位：`6` 个指数位位于 `7:2`，`2` 个尾数位位于 `1:0`，指数偏置为 `48`，有限值有效数带有一个隐含的前导 1。

描述符把 `required_low_zero_bits` 和 `required_high_zero_bits` 都设为 `0`，并且该格式不施加单独的编码有效性检查，因此每个八位编码都是已定义编码。

<!-- PTO-READER-BLOCK: arch-format-e6m2-rules role=rules-interactions -->
## 分解与分类

`E6M2FiniteDecomposition` 对除 `0xff` 以外的每个编码都返回可用分解：符号为 false，整数有效数为 `4` 加上尾数，二进制指数等于指数字段减 `48` 再减 `2`。

`E6M2FiniteValue` 返回 `(4 + fraction) / 4 * FP19PowerOfTwo(exponent - 48)`，`ClassifyE6M2` 对 `0xff` 返回静默 NaN，对其他每个编码返回正规格化数类别。

编码 `0x00` 到 `0xfe` 都是有限正规格化数，`0xff` 是静默 NaN 编码且没有有限值分解；该格式没有零、带符号零、次正规数、无穷大和信号 NaN。

设计要点：为可用性写 `FALSE` 而不是任意有效数，可以避免调用方把非有限载体的占位字段当作数值读取，因此必须先查看可用性标志。

<!-- PTO-READER-BLOCK: arch-format-e6m2-boundaries role=boundaries -->
## 边界与确切编码

设计要点：全 1 编码在求有限值之前就被排除，因此 `E6M2FiniteValue` 对 `0xff` 触发断言，调用方必须先分类编码，而不能对整个编码空间逐个调用该解码器。

`0x00` 是最小有限编码，表示 `2^-48`；`0xfe` 是最大有限编码，表示 `1.5 * 2^15`。

设计要点：该格式根本不声明零编码，因此零不是本类型的值；把零源转换到 `E6M2` 会发布 `0x00` 载体，而它表示 `2^-48`。

按函数顺序阅读本页：先从描述符取得字段位置，在需要值类别时调用分类函数，在需要精确有效数与指数时调用分解函数。

## 非规范阅读示例

本例说明当前的 ASL 归属单元，不替代规范操作。

`0xff` 既是唯一的静默 NaN 编码，也是 `E6M2CanonicalNaN` 返回的规范 NaN，并且 `E6M2FiniteValue` 断言其参数不是 `0xff`。

由于每个编码都包含隐含的前导 1，基准缩放永远不为零，因此除非 `E6M2` 字段为 `0xff`，缩放字总是有已定义的有限基准。
