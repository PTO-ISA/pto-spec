## 用途与范围

`E3M2` 是已分配的 PTO 数值格式，其数值占据 `8` 位载体中的六位 lane；本单元拥有它的描述符、编码有效性、有限值分解、值分类和有符号零编码。

三位指数和两位尾数带来了比 `E2M3` 更宽的范围，代价是一位尾数。

设计要点：该记录把载体宽度与逻辑 lane 宽度分开，因此打包类型在一个载体中报告两个 lane，而单 lane 类型在其载体中只报告自己的 lane 宽度。

<!-- PTO-READER-BLOCK: arch-format-e3m2-concepts role=concepts-state -->
## 载体与字段

描述符使用 `8` 位载体、`6` 位逻辑 lane，并且每个载体包含 `1` 个 lane。

lane 的符号位位于 `5`，`3` 个指数位位于 `4:2`，`2` 个尾数位位于 `1:0`，指数偏置为 `3`；载体的 `7:6` 位被约束为零。

描述符把 `required_high_zero_bits` 设为 `2`，因此载体中只有低六位属于该数值。

<!-- PTO-READER-BLOCK: arch-format-e3m2-rules role=rules-interactions -->
## 分解与分类

`E3M2EncodingValid` 报告载体 `7:6` 位是否都为零；`E3M2FiniteDecomposition` 先拒绝约束位不为零的载体，然后返回可用性、符号、整数有效数和二进制指数，使精确值为 `(-1)^sign * UInt(significand) * 2^exponent`。

`ClassifyE3M2` 把原始 lane 归入零、次正规数或正规数类别；该格式没有无穷大和 NaN 编码，因此每个六位 lane 都表示有限值。

指数字段为零且尾数非零时选择次正规数形式，且每个非零 lane 都分类为带符号的有限值。

<!-- PTO-READER-BLOCK: arch-format-e3m2-boundaries role=boundaries -->
## 边界与确切编码

设计要点：约束载体的两个高位，意味着一个八位存储字节只能承载一个 `E3M2` 值，未使用的位保持为零，而不会被重新解释为更宽的指数。

`0x01` 是最小正次正规数，表示 `1 * 2^-4`；`0x08` 是第二个正规格化数，表示 `4 * 2^-4`，即 `1 * 2^-1`。

设计要点：`0x00` 与负编码是同一量值的两个独立编码，因此保留符号位的调用方仍能分辨结果来自哪一个，即使二者都与零相等。

按函数顺序阅读本页：先从描述符取得字段位置，在需要值类别时调用分类函数，在需要精确有效数与指数时调用分解函数。

## 非规范阅读示例

本例说明当前的 ASL 归属单元，不替代规范操作。

`0x1f` 是最大有限值，分解为有效数 `7` 和指数 `2`，即 `1.75 * 2^4`。

`0x00` 和 `0x20` 分别是正零与负零编码，`0x40` 不是合法的 `E3M2` 编码，因为 `6` 位被置位。
