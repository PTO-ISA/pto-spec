## 用途与范围

`FP64` 是已分配的 PTO 浮点格式，其 lane 占满整个 `Word`；本单元是它的布局、有限值分解、值分类、规范 NaN 和有符号零编码的确切所有者。

它的十一位指数和五十二位尾数使它成为本数据类型族中最宽的格式。

设计要点：该记录把载体宽度与逻辑 lane 宽度分开，因此打包类型在一个载体中报告两个 lane，而单 lane 类型在其载体中只报告自己的 lane 宽度。

<!-- PTO-READER-BLOCK: arch-format-fp64-concepts role=concepts-state -->
## 载体与字段

描述符使用 `64` 位载体、`64` 位逻辑 lane，并且每个载体包含 `1` 个 lane。

lane 的符号位位于 `63`，`11` 个指数位位于 `62:52`，`52` 个尾数位位于 `51:0`，指数偏置为 `1023`。

描述符把 `required_low_zero_bits` 和 `required_high_zero_bits` 都设为 `0`，因此每个六十四位 lane 都是已定义编码。

<!-- PTO-READER-BLOCK: arch-format-fp64-rules role=rules-interactions -->
## 分解与分类

`FP64FiniteDecomposition` 返回可用性、符号、整数有效数和二进制指数，使精确值为 `(-1)^sign * UInt(significand) * 2^exponent`。

`ClassifyFP64` 把原始 lane 归入零、次正规数、正规数、无穷大或 NaN 类别，因此该格式除有限值外还支持无穷大、静默 NaN 和信号 NaN。

指数字段为零且尾数非零时选择次正规数形式；全 1 指数永远不是有限值：尾数为零给出无穷大，尾数非零给出 NaN 类别。

设计要点：为可用性写 `FALSE` 而不是任意有效数，可以避免调用方把非有限载体的占位字段当作数值读取，因此必须先查看可用性标志。

<!-- PTO-READER-BLOCK: arch-format-fp64-boundaries role=boundaries -->
## 边界与确切编码

全 1 指数分支返回不可用的分解，而不是再分出无穷大或 NaN 分支；因此分解报告该格式的限制，而 `ClassifyFP64` 报告值类别。

设计要点：返回的指数是整数，其声明范围可达 `-1074`，因此最小载体的次正规数形式无需宿主算术即可表达。

设计要点：`0x00` 与负编码是同一量值的两个独立编码，因此保留符号位的调用方仍能分辨结果来自哪一个，即使二者都与零相等。

按函数顺序阅读本页：先从描述符取得字段位置，在需要值类别时调用分类函数，在需要精确有效数与指数时调用分解函数。

<!-- PTO-READER-BLOCK: arch-format-fp64-example role=example-usage -->
## 非规范阅读示例

本例说明当前的 ASL 归属单元，不替代规范操作。

`0x1` 是最小正次正规数，表示 `1 * 2^-1074`；`0x0010000000000000` 是第一个正规格化数，表示 `0x0010000000000000 * 2^-1074`，即 `1 * 2^-1022`。

`0x7fefffffffffffff` 是最大有限值，分解为有效数 `0x001fffffffffffff` 和指数 `971`。
