## 用途与范围

`HF32` 是已分配的 PTO 浮点格式，存储在 `32` 位载体中；本单元是它的布局、编码有效性、有限值分解、分类、规范 NaN 和有符号零编码的确切所有者。

它的十一位尾数比 `TF32` 的尾数宽一位，因此这两个截断载体是不同格式，即使两者都占 `32` 位。

<!-- PTO-READER-BLOCK: arch-format-hf32-concepts role=concepts-state -->
## 载体与字段

设计要点：从 `FP32` 到 `HF32` 的舍入边界不属于本单元，因此哪些被丢弃的 `FP32` 尾数位可以接受，由执行转换的调用方决定。

描述符使用 `32` 位载体、`32` 位逻辑 lane，并且每个载体包含 `1` 个 lane。

lane 的符号位位于 `31`，`8` 个指数位位于 `30:23`，`11` 个尾数位位于 `22:12`，指数偏置为 `127`，并且有 `12` 个必须为零的低位。

设计要点：必须为零的位数正好是更宽载体必须丢弃的低位，因此由更宽格式缩窄得到的载体总能通过编码检查，而任何这些位被置位的载体都不可能是该缩窄的结果。

设计要点：该记录把载体宽度与逻辑 lane 宽度分开，因此打包类型在一个载体中报告两个 lane，而单 lane 类型在其载体中只报告自己的 lane 宽度。

<!-- PTO-READER-BLOCK: arch-format-hf32-rules role=rules-interactions -->
## 分解与分类

设计要点：由于十一位尾数位于 `22:12`，调用方从 `FP32` 缩窄时丢弃的每一位，都是本格式要求为零的 `12` 个低位之一。

`HF32EncodingValid` 报告这 `12` 个必须为零的低位是否全为零，并且描述符把 `required_high_zero_bits` 设为 `0`。

`HF32FiniteDecomposition` 先拒绝 `12` 个低位不全为零的任何载体，然后返回可用性、符号、整数有效数和二进制指数，使精确值为 `(-1)^sign * UInt(significand) * 2^exponent`。

设计要点：为可用性写 `FALSE` 而不是任意有效数，可以避免调用方把非有限载体的占位字段当作数值读取，因此必须先查看可用性标志。

设计要点：截断尾数改变的是数值能被表示得多细，而不改变指数编码，因此截断载体保留 `FP32` 的范围，并在整个范围内一致地损失精度。

<!-- PTO-READER-BLOCK: arch-format-hf32-boundaries role=boundaries -->
## 边界与确切编码

`ClassifyHF32` 把原始 lane 归入零、次正规数、正规数、无穷大或 NaN 类别，`HF32CanonicalNaN` 返回 `0x7fc00000`。

指数字段为零且尾数非零时选择次正规数形式；全 1 指数永远不是有限值：尾数为零给出无穷大，尾数非零给出 NaN 类别。

设计要点：`0x00` 与负编码是同一量值的两个独立编码，因此保留符号位的调用方仍能分辨结果来自哪一个，即使二者都与零相等。

按函数顺序阅读本页：先从描述符取得字段位置，在需要值类别时调用分类函数，在需要精确有效数与指数时调用分解函数。

<!-- PTO-READER-BLOCK: arch-format-hf32-example role=example-usage -->
## 非规范阅读示例

本例说明当前的 ASL 归属单元，不替代规范操作。

例如，`0x00001000` 是最小正次正规数，分解为正的有效数 `1` 和指数 `-137`；而 `0x7f800000` 是正无穷大，并且报告没有有限值分解。

设计要点：要求 `12` 个低位为零，使每个合法的有限 `HF32` 载体所表示的值与相同位模式的 `FP32` 载体完全相同，因为位于 `22:12` 的十一位 `HF32` 尾数就是 `FP32` 尾数的高十一位；没有这条规则，同一个 32 位模式就可以同时表示一个 `FP32` 值和一个量值不同的 `HF32` 值。
