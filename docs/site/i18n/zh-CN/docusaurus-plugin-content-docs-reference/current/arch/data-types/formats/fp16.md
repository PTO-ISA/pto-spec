## 用途与范围

`FP16` 是已分配的 PTO 浮点格式，存储在 `16` 位载体中；本单元是它的布局、有限值分解、值分类、规范 NaN 和有符号零编码的确切所有者。

它使用五位指数和十位尾数，因此相对 `BF16` 是以指数范围换取更细的值网格。

设计要点：该记录把载体宽度与逻辑 lane 宽度分开，因此打包类型在一个载体中报告两个 lane，而单 lane 类型在其载体中只报告自己的 lane 宽度。

<!-- PTO-READER-BLOCK: arch-format-fp16-concepts role=concepts-state -->
## 载体与字段

描述符使用 `16` 位载体、`16` 位逻辑 lane，并且每个载体包含 `1` 个 lane。

lane 的符号位位于 `15`，`5` 个指数位位于 `14:10`，`10` 个尾数位位于 `9:0`，指数偏置为 `15`。

描述符把 `required_low_zero_bits` 和 `required_high_zero_bits` 都设为 `0`，因此每个十六位 lane 都是已定义编码。

<!-- PTO-READER-BLOCK: arch-format-fp16-rules role=rules-interactions -->
## 分解与分类

`FP16FiniteDecomposition` 返回可用性、符号、整数有效数和二进制指数，使精确值为 `(-1)^sign * UInt(significand) * 2^exponent`。

`ClassifyFP16` 把原始 lane 归入零、次正规数、正规数、无穷大或 NaN 类别，因此该格式除有限值外还支持无穷大、静默 NaN 和信号 NaN。

指数字段为零且尾数非零时选择次正规数形式；全 1 指数永远不是有限值：尾数为零给出无穷大，尾数非零给出 NaN 类别。

设计要点：为可用性写 `FALSE` 而不是任意有效数，可以避免调用方把非有限载体的占位字段当作数值读取，因此必须先查看可用性标志。

<!-- PTO-READER-BLOCK: arch-format-fp16-boundaries role=boundaries -->
## 边界与确切编码

全 1 指数分支返回不可用的分解，而不是再分出无穷大或 NaN 分支；因此分解报告该格式的限制，而 `ClassifyFP16` 报告值类别。

设计要点：五位指数给出的正规数范围是 `2^-14` 到略小于 `2^16`，因此精度适合 `FP32` 的数值仍可能使 `FP16` 上溢，必须由调用方处理。

设计要点：`0x00` 与负编码是同一量值的两个独立编码，因此保留符号位的调用方仍能分辨结果来自哪一个，即使二者都与零相等。

按函数顺序阅读本页：先从描述符取得字段位置，在需要值类别时调用分类函数，在需要精确有效数与指数时调用分解函数。

## 非规范阅读示例

本例说明当前的 ASL 归属单元，不替代规范操作。

`0x0001` 是最小正次正规数，表示 `1 * 2^-24`；`0x0400` 是第一个正规格化数，表示 `0x0400 * 2^-24`，即 `1 * 2^-14`。

`0x7bff` 是最大有限值，分解为有效数 `0x07ff` 和指数 `5`，即 `1.9990234375 * 2^15`。

pure func ClassifyFP16(value: bits(16)) => NumericValueClass
begin
    let exponent = value[14:10];
    let fraction = value[9:0];
    if exponent == Ones{5} then
